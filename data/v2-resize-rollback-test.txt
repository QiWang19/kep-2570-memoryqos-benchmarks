Test pod: Burstable (requests=128Mi/50m, limits=256Mi/100m), pause container, resizePolicy=NotRequired

Procedure:
  1. Start kubelet with MemoryQoS=true, TieredReservation, InPlacePodVerticalScaling=true (default)
  2. Create Burstable pod, verify cgroup values
  3. Disable MemoryQoS (set false, remove memoryReservationPolicy), restart kubelet
  4. Verify stale container-level values persist
  5. Trigger in-place resize: 128Mi/256Mi -> 192Mi/384Mi via resize subresource
  6. Check whether resize clears stale memory.high

FINDING: InPlacePodResize successfully clears stale memory.high after MemoryQoS rollback.
The kubelet (PR #139377) sets memory.high=max in the Unified map when MemoryQoS is disabled,
and CRI-O (PR cri-o/cri-o#9820) passes the Unified map through UpdateContainerResources.
Both fixes are required — without the CRI-O fix, the Unified map is silently dropped.

Container-level memory.low remains stale at 128 MiB but is effectively neutralized because
the parent QoS-class cgroup memory.low=0, and cgroup v2 memory protection is hierarchical.
